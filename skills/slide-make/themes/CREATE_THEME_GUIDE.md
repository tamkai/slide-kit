# 新しいテーマを「対話で」作るガイド

ゼロから slide-make のテーマを1つ完成させるための、Claude 主導の対話フロー。

`README.md` は「テーマの型(何を満たすファイルが要るか)」の仕様書。
こちらは「Claude がユーザーに質問しながら、その型を埋めていく進め方」。
両方を使う — 質問の進め方はこのファイル、出力物の仕様は README.md。

> **Claude へ**: ユーザーが「新しいテーマを作りたい」と言ったら、この
> ファイルの Step 1〜6 を順に進める。各 Step で `AskUserQuestion` を使い、
> 回答を集めてからテーマ資産を生成する。勝手に色やフォントを決めない。
> 先に `<plugin>/skills/slide-plan/references/` の PRINCIPLES.md / MODES.md /
> ACCENT_PLACEMENT.md を読んでおくこと。

---

## Step 1: Voice を引き出す

テーマは色やフォントではなく「声(Voice)」から始める。パレットから
入ると AI 生成っぽい多色ベタ塗りになる。まず言葉を引き出す。

**質問する(AskUserQuestion / 自由記述も促す)**:
- このテーマで作る資料は、誰が・どんな場で見る? (例: 経営者向けセミナー、社内提案、ピッチ)
- 見た人に持ってほしい「感触」は? (例: 落ち着く / 高揚する / 信頼できる / 手づくり感)
- 一番近い場所・物・時間帯を1つ挙げると? (例: アトリエの朝、夜の書斎、真新しい体育館)

**まとめる**: 回答から Voice を **1文** に言語化し、ユーザーに確認する。
> 例(papercraft): 「アトリエの朝 — 紙とハサミの手仕事感。静かで温かく、急かさない声」

Voice が1文で書けないうちは次に進まない。

---

## Step 2: Document↔Workshop 軸の位置を決める

`references/design-modes.md` の連続軸で、このテーマがどこを狙うか決める。

**質問する**:
- このテーマの資料は「読んで理解する(Document)」寄り? 「その場で
  体験させる(Workshop)」寄り? (例で示す: 配布教材=Document 寄り /
  登壇プレゼン=Workshop 寄り)
- 1枚あたりの情報量は「みっちり読ませる」か「キーワードだけ」か

**反映する**: この位置がジャンプ率(`--text-hero` の大きさ)を決める。
Document 寄りなら抑制的(8rem 級)、Workshop 寄りなら極端(12rem 級)。

---

## Step 3: パレットを決める

色名から入らない。「**何を効かせたいか**」から逆算する。

**質問する**:
- 主役の文字色(ink)は? 真っ黒は避ける前提で、墨寄り/茶寄り/紺寄り など
- 地の色(paper)は? 純白 / オフホワイト / クリーム / 淡色
- **効かせ色(accent)は1色**。資料の中で一番目を引かせたい所に使う色。
  どんな印象? (情熱=赤系 / 信頼=青系 / 温かみ=金茶系 など)
- 効かせ色を1色だけにするか、識別用にサブ2色まで許すか
  (3軸の図など色分けが要るなら 2〜3 色)

**展開する**: キーカラーから ink / paper / accent / muted / subtle の
5トークンに展開する。`README.md` Step 3 の必須変数。

**禁則を確認**: 効かせ色の使用上限を決める(例: 画面の5%未満、または
1スライド2色まで)。これを theme.md の禁則に書く。

---

## Step 4: 背景の役割を設計する

背景は「1枚で全部まかなう」を避け、**役割別に複数種**を用意する
(`references/background-generation.md` の原則1)。

**質問する**:
- 背景に質感・装飾を入れる? (紙テクスチャ / 無地 / 幾何パターン など)
- ページの種類を洗い出す: 表紙、本文(中身が詰まる)、まとめ、
  キーメッセージ(文字主役) ── それぞれ何種類要るか
- 装飾を入れるなら「中央は読む余白として空ける」前提でよいか

**設計する**: 役割別の背景クラス表を作る。例:

| bg-* | 装飾の配置 | 用途 |
|---|---|---|
| bg-cover | 上下に帯+隅に飾り / 中央広い | 表紙・章扉 |
| bg-corners | 四隅に極小 / 中央最大に空く | 本文・図解 |
| bg-minimal | ほぼ無地 | キーメッセージ |

背景画像が要るなら、この後 `references/background-generation.md` の
手順で jinn-image 生成へ進む。

---

## Step 5: 試作1枚で検証する

いきなり全資産を作らない。

1. Step 1〜4 の決定で、**代表的なスライドを1枚だけ** HTML で作る
   (表紙 or 本文のどちらか、Voice が一番出る方)
2. ブラウザ表示 or スクショで、ユーザーに見せる
3. Voice と合っているか確認 → 合っていなければ Step 1〜3 に戻る
4. OK が出てから本生成へ

試作を飛ばすと、方向がずれたとき全部やり直しになる。

---

## Step 6: テーマ資産を生成し、動作検証する

承認が出たら、`README.md` の Step 2〜8 に沿って一式を生成する。

**生成する(出力先・仕様は README.md)**:
- `themes/{name}/theme.css` — CSS 変数 + 意味クラス
- `themes/{name}/theme.md` — Voice / パレット / 背景の役割 / 禁則 /
  得意・不向き / L1-L6 実装方針 / 実装チェックリスト
- `themes/{name}/fonts.html` — Google Fonts の `<link>`
- `themes/{name}/assets/` — 背景画像・ロゴ等

**動作検証(README.md Step 8)**:
- 7枚の小デッキ(表紙 / 章扉 / 本文 / 図解 / キーメッセージ /
  まとめ / Closing)を生成し、Voice と一致するか視覚確認
- `html-build-loop.md` のスクショ検証ループを通す
- 必要なら `pptx-conversion-rules.md` で PPTX 化まで確認

**最後に**: `README.md` の「既存テーマ」欄に新テーマを1行追加する。

---

## 実例: papercraft テーマはこの対話でこう決まった

このガイドを実際に通すと何が起きるかのサンプル。

| Step | 決まったこと |
|---|---|
| 1 Voice | 「アトリエの朝 — 紙とハサミの手仕事感。静かで温かく、急かさない」 |
| 2 軸 | Document 寄り(セミナー配布教材が主用途)→ ジャンプ率は抑制的、`--text-hero` は 8rem |
| 3 パレット | ink=柔らかい墨グリーン #3A3F38 / paper=クリーム #F3EEE3 / accent=ゴールド #C4A057。識別用に sage / terracotta のサブ2色を許可(3軸の図のため)。禁則=アクセント1スライド2色まで |
| 4 背景 | 紙テクスチャ。役割別4種 — cover / corners / wrap / minimal。装飾は端へ、中央は読む余白 |
| 5 試作 | 本文ページ(2つの山の図解 + 要点ボックス)を1枚作って検証 → トーン OK |
| 6 資産 | `themes/papercraft/` に theme.css / theme.md / textbook.css / fonts.html / assets/backgrounds(JPEG 最適化4枚) |

papercraft は配布教材(テキストブック)用途が強かったため、`theme.css`
に加えて `.tb-*` クラス群の `textbook.css` も持つ2モード構成になった。
用途が分かれるテーマでは、こうしたモード別 CSS を足してよい。
詳細は `themes/papercraft/theme.md` を参照。
