# HTML スライドを「チェックしながら量産する」ワークフロー

複数枚の HTML スライドを、品質を揃えながら作る手順。
テーマ非依存の汎用ワークフロー。papercraft で 24枚 + 32枚 を実証済み。

slide-make 本体の Phase 4(HTML 生成)を、**枚数が多いとき**にどう
回すかの実務手順。Phase 6(チェックリスト確認)を「スクショ検証ループ」
として具体化する。

---

## 全体の流れ

```
構成案(md) → 完成見本を1枚作る → サブエージェント並列生産
   → スクショ検証ループ → 進捗トラッカーで管理 → 完了
```

---

## ステップ1: 構成案と完成見本を先に固める

量産の前に2つを用意する。

1. **構成案(Markdown)** — 各ページの見出し・本文・要点・図解プランを
   md で書き出す。`SLIDES_v4.md` のような1ファイル。これがソース。
2. **完成見本 HTML を1枚** — 代表的なページタイプを1枚だけ本気で作り、
   ユーザー承認を取る。これが「品質の基準」になる。

見本なしで量産を始めると、ページごとに微妙に作りが変わって揃わない。

---

## ステップ2: サブエージェントで並列生産

枚数が多い(20枚以上)ときは、サブエージェントに分担させる。
**3体程度に分割**すると速く、かつ品質が揃う。

各サブエージェントに必ず渡すもの:

- **共通の仕様書** — テーマの theme.md / 制作仕様(サイズ・クラス・禁則)
- **完成見本 HTML** — ステップ1で作った1枚。「このクオリティに揃えろ」
- **担当ページの構成案** — md から該当ページ分を抜き出して渡す
- **出力先とファイル名規則** — `PXX_<slug>.html` など

仕様書 + 完成見本をセットで渡すと、3体の出力がほぼ揃う(実証済み)。
逆に仕様書だけだと各自の解釈でばらつく。

---

## ステップ3: スクショ検証ループ

生成しただけでは終わらない。**必ず目で見る**。

```
HTML を PNG 化 → Read で目視 → 問題を直す → 再 PNG 化 → 再確認
```

### スクショの撮り方

Playwright で `.slide` 要素だけをキャプチャする。検証用スクリプトの
ひな型は `references/scripts/` 配下、または下記をそのまま使う:

```python
from playwright.sync_api import sync_playwright
from pathlib import Path
import glob

ROOT = Path("<プロジェクトルート>")
OUT = ROOT / "outputs" / "screenshots"
OUT.mkdir(parents=True, exist_ok=True)
sources = sorted(glob.glob(str(ROOT / "<slides ディレクトリ>/*.html")))

with sync_playwright() as p:
    browser = p.chromium.launch()
    ctx = browser.new_context(
        viewport={"width": 1280, "height": 720},
        device_scale_factor=1,            # ← 等倍。下記の注意参照
    )
    page = ctx.new_page()
    for src in sources:
        name = Path(src).stem
        page.goto(f"file://{src}")
        page.wait_for_load_state("networkidle")
        page.wait_for_timeout(500)
        page.locator(".slide").first.screenshot(path=str(OUT / f"{name}.png"))
        print(f"saved {name}.png")
    browser.close()
```

### 検証の作法

- **1枚ずつ Read で確認する**。まとめて見ようとしない
- **`device_scale_factor=1`(等倍)** を基本にする。2x にすると画像が
  2560px になり、Read の画像サイズ上限(2000px 級)に引っかかって
  確認できない事故が起きる(実証済み)。細部を拡大したいときだけ
  一時的に上げ、対象を1枚に絞る
- 見るポイント: テキストのはみ出し・見切れ、要素の重なり、余白の
  不均一、コントラスト不足、レイアウト崩れ、文字化け
- **問題を1つ直したら、その枚を再キャプチャして再確認する**。
  1つの修正が別の崩れを生むことがある

### 大量ページは QA をサブエージェントに任せる

全ページの目視は、スクショを撮ったあとサブエージェントに渡すと速い。
「問題があると仮定して探せ」と指示し、スライド番号ごとに issue を
報告させる。自分で全部見るより漏れが少ない(staring blind を避ける)。

---

## ステップ4: 進捗トラッカーで再開可能にする

量産は時間がかかり、途中でセッションが切れる。進捗ファイルを1つ作り、
「どこまでやったか」を常に最新化する。別セッションで `/start` →
トラッカーを見て続行できる。

トラッカーの形式は `background-generation.md` の進捗トラッカー節と
同じ。チェックリスト + 「次にやること」 + ログ。

---

## ステップ5: 完成の確認

- 全ページのスクショで崩れゼロを確認
- 1280×720 に収まり、はみ出しがない
- テーマの theme.md の実装チェックリストを通す
- 必要なら PDF 化(`references/pptx-conversion-rules.md` 参照)
