# スライドのレイアウトタイプ（slide-make）

同じ構成JSONから、用途別に2タイプのスライドを生成できる。

## タイプA — 講演用（口頭駆動・Bと同等の情報量が基本）

- 用途: セミナーで喋りながら見せる。スクリーン投影用
- 構成: テキストゾーン（`title` 特大 + `lead_B` 結論ひとこと + `body_B` 小さめ本文2〜3行 + 小さなキャプション）と、図のグラフィックゾーンの非対称バランス + たっぷり余白
- 焼く文字: **原則 `title` + `lead_B` + `body_B` + キャプション**（Bと同等の情報量。2026-08 実証: 図だけのスライドは話者依存が強すぎ、聞き手も置いていかれる）
  - タイトル < 結論 < 本文のサイズ階層を明確に指示する
  - **文字少・図主役はオプション**。クライマックス等、意図した枚（tension 8以上など）だけ `title` のみに絞る
- `labels` は**画作りのヒント（プロンプト素材）であり、既定では文字として焼かない**。全スライドにタグ行が並ぶと「図＋タグ数個」の同一構図が続き、テンプレ感（AI生成っぽさ）の主因になる。焼いてよいのは、情報系スライド（tension 低〜中）で図の要素に短い名札が要る時だけ。**text-hero・クライマックス（tension 8以上）には絶対に焼かない**（「ほぼ1要素」の強度が死ぬ）
- プロンプト素材: スタイル定義 + そのスライドの `title` / `lead_B` / `body_B` / `visual_brief`（タグを焼くと判断した枚のみ `labels` を名札として追加）

## タイプB — 読んで分かる（配布・自習用）

- 用途: 単体で読んで意味が取れる。配布資料・自習用
- **必ず上下分割レイアウトにする**（下記の失敗を避けるため）

### タイプBの失敗と正解（重要・実証済み）

**失敗**: Aの完成した図に、後付けで本文3行を中央にベタ打ちする
→ 文字が「付箋」のように浮き、フォント階層もなく、ダサくなる。

**原因**:
1. Aの絵が既に完成しているので、文字の居場所が設計されていない（後付け付箋になる）
2. フォント・行間・サイズ階層を指定しないと、AIが本文をのっぺり描画する
3. 「Aと同構図で」と縛ると、図も大きいまま文字も入る中途半端になる

**正解 = 上下分割**:
- 【上段 約45% = テキスト主役】地よりわずかに明るい/縁取りのある**横長パネル（角丸・軽い影）の上に文字を載せる**（浮かせない）。中身は上から: 小さめタイトル → 大きい「結論ひとこと」(`lead_B`) → 小さめ本文2〜3行(`body_B`)。**タイトル < 結論 < 本文 のサイズ階層を明確に**（結論が最大）
- 【下段 約55% = 横長図】16:9横幅いっぱいの横長ジオラマ。Aの図構図をそのまま下段に置ける（左右分割だと図を縦圧縮する無理がある）。タグを焼くと判断した枚のみ、図の脇に小さく

> なぜ上下分割が勝つか: ①文字に専用ゾーン（パネル）ができる ②サイズ階層が出る ③Aの横長図資産をそのまま使える ④本文の1行を長く取れて読みやすい。左右分割・中央ベタ打ちより全項目で優れる（3案比較で実証）。

- プロンプト素材: スタイル定義 + `title` / `lead_B` / `body_B` / `visual_brief` + 「上下分割」レイアウト指示 + 既存B画像をお手本に（`labels` は画作りのヒント。焼くのは名札が要る枚のみ）

## 共通の生成プロンプト要点

- アスペクト: 「横長・ワイド・16:9・landscape widescreen」と方向語を重ねる
- スタイル定義（`styles/<name>.txt`）の配色・質感・トーンを厳守
- 指定した文字（title、Bは lead_B/body_B も。labels は焼くと判断した枚のみ）以外の文字・段落は描かない
- ONE clear focal idea・たっぷり余白
- 既完成の同デッキ画像をお手本参照させて世界観を揃える（取り違え注意）
