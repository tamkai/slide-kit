# タイプD — 新しい画風を受け取る

**画風を渡されたら、内容を作り始める前に見本を1枚作って見せる。** 見本はベン図、循環図、フロー図と表紙の4コマで、中身は毎回同じ。OK なら画風パックとして保存し、次回からは名前で呼べる。

## 原則: 描き方だけを切り出す

画風の指定には、2種類のものが混ざっている。

| | 例 | 生成に渡すか |
|---|---|---|
| **描き方（how）** | 線、形、色、質感、光、余白、文字、素材 | 渡す |
| **描くもの（what）** | 特定の人物やキャラ、マスコット、小道具、場面、モチーフ | 既定では渡さない |

描くものが混ざると、**図の内容を押しのけて主役を取る**。2026-11-06 の実証では、家族キャストが書かれた画風の原文を渡すと、「使わない」と後から指示しても家族が大きく描かれた。原文から描き方だけを切り出して渡すと、家族は消えて図が主役になった。Neo Museum も、題材の彫像を分けると、大理石の円盤や石板そのものが図になった。**消す指示を足すのではなく、はじめから渡さない。**

見分け方は「**まったく別のテーマの資料にそのまま使えるか**」。使えなければ描くものに分ける。
素材は描き方、題材は描くもの。「大理石の質感」は描き方で、「大理石の彫像」は描くもの。

描くものも捨てない。`what.txt` に残し、本人が望めば `--with-what` で戻す。デッキ固有の人物は画風ではなく構成JSONの `cast` に書く。

## 手順

### 1. 受け取る

原文は `source.md` にそのまま保存し、**書き換えない**。生成に渡す文章は別に作る。

| 渡され方 | 扱い |
|---|---|
| 長文プロンプト | `source.md` に保存し、描き方と描くものに分ける |
| 参照画像 | `refs/` に保存し、Claude が見て言葉に起こす。生成時にも参照として渡す。文字が写っていない画像や部分を選ぶ（写っていると混入する） |
| PDF・PPTX | ページを画像にして、参照画像と同じ扱い |
| 名前だけ | パックから探す。なければ候補の見本を見せて選んでもらう。**名前だけで作らない**（名前が違っても似た絵になる） |
| 文章と画像の両方 | 見た目は画像、意図は文章を優先。食い違いは見本の段階で本人に聞く |
| Webのスタイル集のYAML | 長文プロンプトと同じ。出どころを `pack.json` に書く |

### 2. 図の部品を定義する

画風の指定には、図の部品の描き方がまず書かれていない。7つを定義し、**どこから来たかを必ず書く**。

| 部品 | 決めること |
|---|---|
| 要素 | ノードや箱を何で描くか。ラベルをどこに置くか |
| つなぎ・矢印 | 線の質。向きが読めるか |
| 重なり | 2つの集合が重なるとどう見えるか |
| 強調 | 主役の1点をどう目立たせるか |
| 人物 | 出すか、大きさはどのくらいか |
| 文字 | 日本語の書体と置き方 |
| 密度 | 余白の量。どこまで情報を載せられるか |

`source` の書き方: 「原文」「画像」「補完」。AIが補った部分を原文のように扱わない。

### 3. 画風パックを作る

```text
$SLIDE_KIT_PACKS/styles/<id>/
├── source.md        原文（書き換えない）
├── how.txt          生成に渡す描き方（英語）
├── what.txt         分けた題材（無ければ空）
├── pack.json        図の部品、参照画像、向き不向き
├── refs/            参照画像（任意）
└── calibration.png  本人が OK した見本
```

```json
{
  "id": "<id>",
  "name": "<表示名>",
  "source": "<出どころ>",
  "how_file": "how.txt",
  "what_file": "what.txt",
  "refs": ["refs/a.png"],
  "ref_note": "Do not reuse the <参照画像の固有の物> from the references.",
  "parts": [
    {"part": "要素", "source": "画像", "en": "Elements: <描き方>"}
  ],
  "fit": {"good": [], "untested": [], "note": ""},
  "calibration": "calibration.png"
}
```

### 4. 見本を作る

```bash
python3 <plugin>/skills/slide-make/scripts/typed_build_prompts.py --calibration --style <id> --out <パック>/_cal
python3 <plugin>/skills/slide-make/scripts/typed_render.py <パック>/_cal --stage calibration
```

内容は `type-d-calibration.txt` に固定してある。**中身を変えない。** 同じ内容で描くから、画風の違いだけを比べられる。

### 5. 自分で確かめてから見せる

`type-d-qa.md` の構造、文字、主役を見る。とくに次の2つ。

- 図が主役か。人物や題材が押しのけていないか
- 文字がすべて指定どおりか。ラベルや番号が抜けていないか

問題があれば `how.txt` か部品の定義を直して作り直す。見本の内容ではなく、画風の側を直す。

### 6. 本人に選んでもらう

Cockpit 内なら `cockpit ask --media` で見本を見せ、次から選んでもらう。

- この画風で進める
- ここを直す（どこを直すかは本人の言葉で聞く）
- この画風はやめる

比べるときは、残す候補を全部同じ内容で並べる。単独で見せない。

### 7. 保存する

OK が出た見本を `calibration.png` として保存し、`pack.json` の `fit` に分かったことを書く。

## 向き不向きは見本で判断する

説明文から「この画風は図に向かない」と予想しない。2026-11-06 の実証では、彫刻写真が主役で矢印の表現がなかった Neo Museum が、画像を渡すだけで図解を描けた。

## 置き場所と権利

- **パックは公開リポジトリに入れない。** 既定の置き場所は非公開の `~/product/slide-kit-packs/`
- 他人の作品や Web のスタイル集から作ったパックは、`source` に出どころを書き、再配布しない
- 案件の資料を参照画像にしたパックは、その案件の外で使えるか確かめる
- 実在の人物の似顔絵、実在のキャラクター、ロゴは描かない
