# タイプA-2 — 読み物インフォグラフィック

**画像スライドなのに、タイトルとリード文だけは編集できる**という作り方。
配布資料・報告書のように「読んで分かる」必要があるデッキ向け。

## 何が違うのか

タイプA-1（講演用）は、口頭説明がある前提で文字を削り、図で見せる。
**このタイプA-2は、発表者がいなくても読み手が理解できることを目的にする。**

```
  ┌──────────────────────────────────────┐
  │ タイトル（編集可能テキスト）           │ ← 上部18%は
  │ リード文（編集可能テキスト・2行）       │   画像側で白く空けておく
  ├──────────────────────────────────────┤
  │                                      │
  │   AI生成インフォグラフィック            │ ← 本文・図・ラベルを
  │   （本文テキストごと画像に焼かれる）      │   一体で焼き込む
  │                                      │
  └──────────────────────────────────────┘
```

**画像の上部18%を白の安全領域として空けさせ、そこにPPTXの編集可能テキストを重ねる。**
これで「AIイラストの絵力」と「直せる文字」が両立する。

タイプA-1の弱点は「誤字を見つけたら作り直し」だが、
**一番直したくなるタイトルとリード文だけは、この方式で直せるようになる。**

| | A-1 講演用 | **A-2 読み物** | B 編集できる |
|---|---|---|---|
| 想定 | 話者が喋る | **単体で読める** | 回覧・修正前提 |
| 文字量 | 少ない | **多い（ビジーで可）** | 中 |
| タイトル/リード | 画像に焼く | **編集可能** | 編集可能 |
| 本文 | 画像に焼く | 画像に焼く | 編集可能 |

## 設計思想（重要）

### 情報密度は「高く」でよい

タイプA-1では「1スライド1メッセージ・盛り込みすぎない」が原則だが、
**A-2ではその原則を意図的に外す**。読み物なので、背景・理由・意味・結論が要る。

これは矛盾ではなく **Document ↔ Workshop 連続軸**（`../../slide-plan/references/design-modes.md`）
の Document 側に振り切った状態。**どちらの端を狙うかを案件ごとに意図して決める**のが正しい。

**情報量を減らすために説明文を省略しない。** 文章を適切な単位に分割し、
カード・見出し・強調・接続線で構造に整理する。

### リード文が主役

リード文は副題でもキャッチコピーでもない。
**それだけを読めば、そのスライドの主張・論点・結論が完全に理解できる文章**にする。

- 対象 / 中心となる主張 / その理由や構造 / 読者が理解すべき意味、を1つの自然な文に統合する
- **70〜105字**を目安、**原則2行・最大2行**
- 改行位置は自動折り返しに任せる。行の長さを揃えるために文章を捻じ曲げない
- 全体をBoldにしない。重要語句のみ1〜2か所をBoldにできる
- **フォントサイズを縮めて収めるのは禁止**。溢れたら推敲して削る
- 根拠のない断定・推測はしない

構成JSONの `lead_B` がこれにあたる。slide-plan の段階でここを作り込む。

### 文体（すべてのテキストに適用）

**です・ます調も、だ・である調も使わない。** 簡潔で端正な説明調にする。

使う: 体言止め / 動詞の連体形・終止形 / 「〜する構造」「〜という位置づけ」「〜が必要」
「〜につながる可能性」/ 「〜により」「〜を通じて」「〜を前提に」

使わない: です・ます・でした・ました・でしょう・だ・である・となるのである

**体言止めを連続させて単語の羅列にしない。** 主語と述語、理由と結論、前提と意味の
関係が読者に伝わる、文章としての流れを保つ。同じ文末形式を機械的に繰り返さない。

報告書・解説記事に適した、客観的で落ち着いた文体。会話的表現・呼びかけ・感嘆・
過度な断定は使わない。

## 手順

### Step 1: スタイルを選ぶ

`styles/infographic-readable.txt` を使う。**上部18%の安全領域の指示が入っている**ので、
このタイプでは他のスタイルに差し替えない（差し替えるなら安全領域の指示を必ず移植する）。

ウェブのギャラリーから持ってきたスタイルを使いたい場合は、
`infographic-readable.txt` の `## CRITICAL: TOP SAFE AREA` セクションを先頭に貼り足す。

### Step 2〜4: 画像を生成・回収する

`type-a-image.md` の Step 2〜4 と同じ（**代表3枚の試作は必須**）。

ただし**目視確認の観点が増える**:
- **上部18%が本当に白く空いているか**（ここが埋まっていたら再生成。テキストが重なる）
- 画像内の日本語が文体規定に従っているか
- 図と文章が同じ論理構造を示しているか
- 単体で読んで理解できるか

### Step 5: PPTX化する（`--readable` を付ける）

```bash
node <plugin>/skills/slide-make/scripts/build_pptx_from_images.js \
     deck_structure.json images/ dist/deck.pptx --readable
```

`--readable` を付けると、画像の上に以下を重ねる:

| | 位置(inch) | フォント | サイズ | 色 |
|---|---|---|---|---|
| タイトル | x0.46 y0.10 w12.42 h0.48 | Gen Interface JP Bold | 28.2pt | `#14243A` |
| リード文 | x0.48 y0.60 w12.36 h0.68 | Gen Interface JP SemiBold | 15.8pt | `#40536A` |

**全スライドで同じ位置に固定する**（ページ間で動くと読み手の目が迷う）。

- タイトルが1行に収まらない場合、まず字間を -0.4pt まで詰め、それでも無理なら 27.4pt まで縮小する。
  スクリプトが自動でやり、縮小したスライド番号を報告する。**報告が出たら、縮小に頼らずタイトルを推敲する**
- リード文が105字を超えるとスクリプトが警告する。**縮小せずに推敲する**

### Step 6: fix と検証

```bash
python3 <plugin>/skills/slide-make/scripts/fix_pptx.py dist/deck.pptx
soffice --headless --convert-to pdf dist/deck.pptx
pdftoppm -png deck.pdf preview
```

**render → fix → re-render を最低1回は回す。** 確認すること:

- タイトルが1行に収まっているか
- リード文が2行以内か、15.8ptが維持されているか
- **リード文と画像本文の間に空きがあるか**（重なっていないか）
- 画像内テキストに誤字・欠字・文字化けがないか
- 各スライドが単体の読み物として成立しているか

画像内テキストに誤りがあった場合、**PowerPointのテキストを重ねて隠さない**。画像を再生成する。

## 納品

このタイプは3点セットで納めると親切:

1. 編集可能な PPTX
2. 確認用 PDF
3. 各スライドの画像生成プロンプトをまとめた Markdown（後から1枚だけ再生成できる）
