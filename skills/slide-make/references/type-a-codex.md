# codex画像生成の運用ノウハウ（slide-make 中核）

実セッションで確立した、codex image_gen でスライドを量産する際の非自明な知見。

## 保存先の癖（最重要）

- codexは生成画像を必ず `~/.codex/generated_images/<uuid>/ig_*.png` に**固定で吐く**
- エージェントに「指定パスへcpせよ」と指示しても**cpが不安定**（成功報告でもファイルが無い／別の場所に独自命名で保存する、等が多発）。`~/.claude/` 配下へは特に書き込み不可
- **対策**: エージェントには「image_genで生成し、生成された絶対パスを必ず報告」とだけ要求。**配置（cp）は呼び出し側で `scripts/collect_images.py` を使って行う**

## ハッシュ重複チェックは必須（取り違え対策）

- codexの並列生成は、**お手本画像に引きずられて隣のスライドと同じ絵を作る「取り違え」が起きる**（例: slide_06のプロンプトでslide_05の絵を生成）
- また、回収時の人手配置でも番号取り違えが起きうる
- **対策**: `collect_images.py` が配置後に全 `slide_NN.png` のmd5重複を検出する。**重複が出たら、その番号だけ再生成する**（再生成プロンプトに「前回◯◯と同じ絵を作った失敗がある。このスライドの主役は△△であって□□ではない」と明示すると直る）
- この重複チェックを**配置の度に必ず回す**。今回これを事後にしたため重複の発見が遅れた

## 出力先

- 成果物は `~/product/` など**codexが書ける場所**に置く（`~/.claude/` 配下は不可）。かつ実装成果物の置き場方針とも整合
- ディレクトリ構成の例:
  ```
  <project>/<deck-name>/
  ├── deck_structure.json
  ├── styles/  （または親のstyleを参照）
  ├── images/      ← タイプA（文字少）
  ├── images_B/    ← タイプB（読ませ版）
  └── *.pptx
  ```

## usage / レート制限

- codexには **5時間枠** と **週次枠** の2軸がある。`try again at HH:MM` の時刻指定エラーは**5時間レート制限**（短時間に大量生成で一時的に当たる）。週次枠が残っていても5時間枠で頭打ちになる
- 大量（20枚×2タイプ等）を一度に回すと当たりやすい。当たったら**時間を置く**か、リセット時刻まで待つ。並列度を落として逐次投入するとバーストを避けられる場合がある
- usageは ChatGPT/Codex の「残り使用量」表示で5時間枠・週次枠を個別に確認できる

## image_gen のプロンプト仕様

- 引数は `{prompt}` のみ。**比率は方向語を重ねて**書く（「横長・ワイド・16:9・landscape widescreen」）。解像度・ピクセル指定は効かない（固定。上げたければ後処理リサイズ）
- **日本語描画は実用十分**（GPT-Image2）。タイトル・短いタグ・2〜3行の説明文すべて崩れず出る。「文字は崩れるから避ける」は過剰な旧前提
- **詳細な設計図（visual_brief）を先に作り込み、取捨選択をAIに委ねる**方が出力が安定する
- スタイル一貫性のため、**既に完成した同デッキの画像を「お手本」としてプロンプトで参照させる**（質感・配色・体裁が揃う）。ただし取り違えに注意（上記）

## エージェント並列のやり方

- ダイナミックワークフロー（Workflow）で各スライドを `agentType: 'codex:codex-rescue'` の並列agentで生成
- 各agentに渡すもの: スタイル定義ファイルのパス、deck_structure.jsonのパスと対象`n`、お手本画像のパス、保存はせず実パス報告のみ
- 戻ってきた「n→実パス」を mapping.json にまとめ、`collect_images.py` で一括配置＋重複チェック
- 欠落・重複が出た番号だけ再生成ループ
