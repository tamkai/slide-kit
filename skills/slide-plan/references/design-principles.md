# 希少性の三原則（Three Principles of Scarcity）

スライドデザインで「AI生成っぽさ」を消し、意図的な強調を効かせるための 3 つのルール。全て同じ根本原理から派生している：

> **99% を意図的に抑えることで、1% が本当に効く。**
> **全部を強調することは、何も強調しないこと。**

この原理を **色** / **レイアウト** / **記号** の 3 軸に分解したのが以下の三原則。

---

## 原則 1: アクセント色の希少性（色の次元）

**ルール**: デッキ内のアクセント色（通常は赤や強調色）の画面占有面積を **5% 未満** に抑える。

### なぜか
- 人間の視線は、色の差分に強く反応する
- アクセント色が 10%, 20% と増えると、視線が分散してどこが強調か分からなくなる
- 5% 以下だと、一目でアクセントの位置が分かる

### 運用
- 赤やアクセント色は、**1 スライドあたり 1-3 箇所程度**に限定
- 大面積の色ベタ塗り（フルブリード赤、カード全体が赤等）は原則禁止
- 小さな `afl-accent-bar`（細いバー）、キーワード 1 語の赤文字、などが典型的な使い方

### よくある違反
- ❌ カード全てに赤い枠線
- ❌ ヘッダーとフッターの両方に赤帯
- ❌ 複数のバッジがどれも赤
- ⭕ 章タイトルに小さな赤バー、クライマックスのキーワード 1 語のみ赤

### テーマ側との関係
具体的なアクセント色（赤なのか青なのか）はテーマが決める。この原則は **「何色であれ、5% 未満」** という比率ルールだけを扱う。

---

## 原則 2: visual-first の希少性（レイアウトの次元）

**ルール**: visual-first（写真/図版が主役）のスライドと、text-heavy（情報密度高め）のスライドの**比率を意図的に設計する**。全スライドを一方に寄せない。

### 連続軸モデル

モードは二択ではなく、visual-first ratio の連続軸として捉える：

```
 0%            20%                           70%          100%
 │─────────────●─────────────────────────────●─────────────│
 読み物          Document Mode              Workshop Mode    投影のみ
 (白書・論文)   (提案書・報告書)           (セミナー・WS)
```

詳細は [MODES.md](MODES.md) 参照。

### スライドの役割 4 種

スライド計画時に、各スライドに以下のいずれかの role を割り付ける：

| Role | 説明 | 文字量 | 写真/図版 |
|------|------|--------|----------|
| `visual-hero` | 写真/図版が画面の主役 | 最小限 | 主役 |
| `visual-support` | 文字とビジュアルが半々 | 中程度 | 半々 |
| `text-hero` | 文字が主役、装飾最小、極大文字 | キーワード級 | なし |
| `text-primary` | 文字主導の情報スライド | 多い | あっても補助 |

### 比率ガイドライン

| モード | visual-first（hero + support）比率 | text-heavy 比率 |
|-------|--------------------------|---------------|
| Reading（白書・論文） | 0-10% | 90-100% |
| Document (report/proposal) | **15-25%**（accent として） | 75-85% |
| Document (projection 寄り) | 25-33% | 67-75% |
| **Workshop / Seminar** | **70-85%** | 15-30% |
| Pure projection | 85-100% | 0-15% |

### なぜか
- 全スライド text-heavy → 読者の認知が飽和、後半が滑り落ちる
- 全スライド visual-first → 情報が伝わらない、読み物として成立しない
- **比率を意図することで、visual-first が "accent" として効く**
- 50% を超えた瞬間、accent 効果は消える（珍しさがなくなるため）

### 運用
- デッキ作成の**一番最初**に `visual_first_ratio` を宣言する
- Document mode なら visual-first は [ACCENT_PLACEMENT.md](ACCENT_PLACEMENT.md) の 5 ポジションに戦略配置
- Workshop mode なら visual-first が基本、情報スライドを例外扱いに

---

## 原則 3: ピクトグラムの希少性（記号の次元）

ピクトグラム / アイコンは「飾り」ではなく「視線誘導の道具」として扱う。使いすぎが **AI 生成っぽさの主因**。

### 原理（常に守る）

- ピクトグラムは**装飾ではなく機能**
- 「なぜこのアイコンが必要か」を**言語化できない配置は削る**
- 判断基準: **「そのアイコンが消えたら意味が変わるか？」** — Yes なら必要、No なら削る
- 「見栄えのため」「なんとなく」「対称性のため」は理由として不十分

### デッキ単位のガイドライン

- **アイコン使用率: 全スライドの 20-30%**（残りは意図的にゼロ）
- アイコン濃度の高いページを**連続させない**（2 連続したら次は必ずゼロページ）
- デッキ全体で「アイコン多めのページ」「アイコン少のページ」「アイコンゼロのページ」が呼吸するように配置
- 箇条書きの全行にアイコンを置くのは**常に禁止**

### ページ単位の目安

- **基本**: 0-2 個
- **機能的配列なら 3-4 個まで許容**:
  - カードが並列しており、各項目を視覚的に区別する必要がある（例: 3 つのサービス、4 つの納品物）
  - 数字 KPI のようにアイコンが意味を補強している
  - アイコンを消したらページの意味が変わる
- **5 個以上**: 原則禁止（遠目に見てアイコンが「パラパラ散らばって見える」状態）
- **飾りの配置なら 0 個**: 機能が説明できないなら、1 個でも削る

### 使っていい瞬間

- カテゴリが明確に違うものを区別するとき（3 つの納品物、2 つのメニュー、5 つのステップ）
- 読者の視線を「ここに止めたい」ランドマークとして
- 言葉より記号の方が速く伝わる概念（→, ↑, ✓, ⚠ など）
- 1 つだけ配置する「孤立したアイコン」（1 つだから目立つ）

### ダメな瞬間

- 箇条書きの全行にアイコン
- カード全枚に違うアイコン（並列装飾のためだけ）
- 本文と同じ意味のアイコン（重複情報）
- 「見栄えのため」「なんとなく」「対称性のため」の配置
- 遠目に見て「パラパラ散らばって見える」状態

### 最終判断

上記のガイドライン・目安はいずれも**原理を実装するための補助線**であって、絶対ルールではない。最後に効くのは：

> **ページを遠目で見て、アイコンが機能しているか、飾りになっているか**

これは**人間の審美**に委ねる判断で、ルール化しきれない領域。迷ったら削る方向で。

### 実証

2026-04-10、実案件の提案書制作で検証：
- 前日版: 全項目にピクトグラム → AI 生成っぽさが残る
- 今回版: 数箇所のみに絞り込み → 絞った箇所が「良いアクセント」として機能、AI 感が消えた

## 三原則の統合運用

3 つは独立ではなく、**同じ希少性原理を 3 つの次元に適用したもの**。全てに共通する運用の核：

### 事前宣言
- 色・レイアウト・記号のそれぞれで、**使用目標を事前に決める**
- 「このデッキは 24 枚、visual-first 7 枚、ピクトグラム 5 枚まで、赤アクセントは 1 スライド最大 3 箇所」のように

### 自己監査
- 生成後、[templates/self_audit_checklist.md](templates/self_audit_checklist.md) で全項目クリア確認
- 不合格なら DECK_PLAN に戻る

### 共通原理の言語化
- 「なぜここに？」と問われて言葉で説明できない装飾は削除
- 「対称性のため」「見栄えのため」は理由として不十分
- 「読者の視線をここに止めたいから」「この 1 語を記憶させたいから」は有効

---

## 既存ルールとの対応表

他のデザインルール群とこの三原則がどう対応するか：

| 希少性原則 | 関連する既存ルール |
|-----------|----------------|
| **色の希少性** | CSS のアクセントカラー設計、ブランドガイドラインの禁則 |
| **レイアウトの希少性** | 情報密度バランス、ヴィジュアルヒエラルキー |
| **記号の希少性** | アイコン・ピクトグラム使用ガイドライン、Emoji 使用方針 |

これらの既存ルールが「禁則リスト」だったのに対し、希少性三原則は **「なぜ抑えるのか」の原理** を提供する。禁則を暗記するのではなく、原理から判断できるようになる。
