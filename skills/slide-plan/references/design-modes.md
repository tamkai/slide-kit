# Modes — Document / Workshop 連続軸モデル

スライドの用途は **「読ませる」か「投影する」かの二択ではなく、連続軸** として捉える。この軸を最初に宣言することが、デッキ設計の全ての判断を支配する。

---

## 連続軸モデル

```
 0%            20%                           70%          100%
 │─────────────●─────────────────────────────●─────────────│
 読み物          Document Mode              Workshop Mode    投影のみ
 (白書・論文)   (提案書・報告書)           (セミナー・WS)

  ←── visual-first ratio が低い    visual-first ratio が高い ──→
  ←── 情報密度が高い                情報密度が低い ──→
  ←── 文字量が多い                  文字量が少ない ──→
  ←── 自己完結                      話者補助 ──→
  ←── 発表者ノート不要              発表者ノート本体 ──→
```

---

## 5 つの代表位置

### ① Reading Mode（0-10%）
- **用途**: 白書、論文、技術文書、マニュアル
- **文字量**: 極大
- **発表者**: 不在（一人で読む）
- **visual-first**: 0-10%（あってもごく控えめ）
- **スライドという形式が本当に適切かを一度疑う**。PDF や Word でよくないか？

### ② Document Mode — 配布資料型（15-25%）
- **用途**: 営業提案書、報告書、配布版ピッチ資料
- **文字量**: 多め、情報密度高い
- **発表者**: 任意（配布が主、補足説明あり）
- **visual-first**: **15-25%** — accent として戦略配置
- **情報の所在**: スライド上（自己完結）
- **パターン**: 情報密度高めのレイアウト（HBF ヘッダーフッター、2 列、3 列カード等）がベース。Accent として visual-first を章扉・クライマックス・CTA に配置
- 発表者ノート: 任意

### ③ Document Mode — 投影配布併用型（25-33%）
- **用途**: 投影しながら説明する提案書、会議用資料
- **文字量**: 中程度、読める粒度と見せる粒度の両立
- **発表者**: 同席して説明
- **visual-first**: **25-33%** — accent 比率を document mode 上限寄りに
- **情報の所在**: スライド + 話者の補足
- **パターン**: document mode ベースに、visual-first accent を多めに配置
- **発表者ノート**: 推奨（話者が何を言うかの骨子を残す）

### ④ Workshop Mode — 投影進行型（70-85%）
- **用途**: セミナー・ワークショップ進行の視覚アンカー
- **文字量**: 最小限、キーワードのみ
- **発表者**: 必須（話者が主、スライドは伴奏）
- **visual-first**: **70-85%**
- **情報の所在**: **発表者ノート ＋ 話者の口**（スライドは視覚アンカー）
- **パターン**: visual-first 中心、text-hero（極大キーワード）、quote 風、fullbleed
- **発表者ノート**: **本体**、必須。話す内容はノートに保存しないと消える

### ⑤ Pure Projection（85-100%）
- **用途**: 基調講演、ビジョナリーステージ
- **文字量**: ほぼなし、1 語 or 写真のみ
- **発表者**: 最重要（スライドは話者の背景）
- **visual-first**: 85-100%
- **発表者ノート**: 必須、デッキ以上に重要

## モード宣言のフォーマット

デッキ作成の**一番最初**に、DECK_PLAN.md の冒頭で以下を宣言：

```yaml
mode: document (projection 寄り)
visual_first_ratio: 25-33%
speaker_notes: required   # または optional / essential
target_audience: 経営層（役員、6-8名）
presentation_context: 会議室で投影、配布資料にもなる
```

### 判断フロー

```
Q1: 配布して一人で読むか、場で投影するか？
├── 一人で読む → Document mode (15-25%)
├── 場で投影する ↓
│
Q2: 発表者は主役か、補足役か？
├── 補足役（資料が主） → Document mode projection 寄り (25-33%)
└── 主役（話者が主、スライドは伴奏） ↓
│
Q3: 文字を読ませるか、キーワードで聴かせるか？
├── 文字も読ませる → Workshop mode 下限 (70%)
└── キーワード中心 → Workshop mode 上限 (80-85%) or Pure Projection
```

## モードごとの設計原則の違い

| 項目 | Document | Document (projection) | Workshop | Pure Projection |
|------|----------|----------------------|----------|----------------|
| visual-first ratio | 15-25% | 25-33% | 70-85% | 85-100% |
| 1 スライドの文字量 | 多い | 中 | 少 | 極少 |
| Tension Map の山 | 4-6 枚に 1 回 | 3-5 枚に 1 回 | 頻繁 | 常に高 |
| text-hero 使用 | 1-2 回 | 2-3 回 | 3-5 回 | 半数以上 |
| 発表者ノート | 任意 | 推奨 | 必須 | 絶対 |
| Accent placement | 厳密に 5 ポジション | 5 ポジション + 余裕 | 自由度高い | 意味を持たない |
| 写真素材の重要性 | 中（accent のみ） | 中〜高 | 高 | 極大 |

---

## 共通原則

モードが違っても、以下は**全モード共通**で適用する：

1. **希少性の三原則**（色・レイアウト・記号） — PRINCIPLES.md
2. **Tension Map 思考** — TENSION_MAP.md
3. **Accent Placement 考え方** — ACCENT_PLACEMENT.md（Document mode で特に重要）
4. **DECK_PLAN.md による事前設計** — 実装前の合意形成

モードは **「これらの原則の適用比率」** を決めるダイヤル。原則そのものは変わらない。

---

## よくある誤り

### ❌ モード未宣言で作り始める
→ 途中で visual-first と text-heavy がバラバラに混ざり、統一感のないデッキになる

### ❌ Document mode なのに visual-first を 50% 超えで配置
→ 「読めない配布資料」になる。アクセント効果も消える

### ❌ Workshop mode なのに情報を全部スライドに書く
→ 話者の役割がなくなる。聴衆は話者ではなくスライドを読み始める

### ❌ モード間を途中で切り替える
→ 同じデッキの前半は document、後半は workshop、のような混在はほぼ失敗する。別デッキに分ける方がよい

### ⭕ 正しい運用例
- 「これは提案書で、配布もするし会議で投影もする」→ **document mode projection 寄り、ratio 25-33%**
- 「これはセミナーの投影専用、スライドは最小限」→ **workshop mode、ratio 75%**
- 「これは営業資料、読まれるのが主、投影は補助」→ **document mode、ratio 20%**
